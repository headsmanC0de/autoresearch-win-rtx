## 14. FAQ — часті питання

### Загальне

**Q: Скільки часу займає один експеримент?**
A: Рівно 5 хвилин тренування + 1–2 хвилини на startup, autotune та evaluation. Разом ~7 хвилин.

**Q: Скільки експериментів можна зробити за ніч?**
A: ~100 (8 годин / ~5 хв на експеримент).

**Q: Чи можна використовувати інший датасет?**
A: Поки що тільки TinyStories. Додавання нових датасетів вимагає зміни `prepare.py`.

### Проблеми

**Q: OOM (Out of Memory) — що робити?**
A: Зменшити `DEVICE_BATCH_SIZE` або увімкнути activation checkpointing (`AUTORESEARCH_FORCE_CHECKPOINTING=1`). Також можна зменшити модель (менший `DEPTH` або `ASPECT_RATIO`).

**Q: val_bpb дуже високий (> 2.0) — що не так?**
A: Модель не вчиться. Перевірити: LR занадто високий? Batch size занадто малий? Архітектура зламана?

**Q: Autotune обирає занадто маленький batch size?**
A: Спробуй `AUTORESEARCH_AUTOTUNE_REFRESH=1` або `AUTORESEARCH_DISABLE_AUTOTUNE=1` з ручним `DEVICE_BATCH_SIZE`.

**Q: Запуск падає з помилкою CUDA?**
A: Перевірити що CUDA драйвери оновлені. PyTorch 2.9.1 вимагає CUDA >= 12.x.

### Платформа

**Q: Чи можна запускати на laptop GPU?**
A: Офіційно не підтримується через варіативність TDP/thermal throttling. Може працювати, але результати будуть нестабільними.

**Q: Чи можна запускати на AMD/Intel GPU?**
A: Ні, форк підтримує тільки NVIDIA RTX.

**Q: WSL чи native Windows?**
A: Обидва працюють. WSL зручніший для автономного агента (Claude CLI). Native Windows — через PowerShell.

### Рівень 2: Експериментатор

## 16. Глосарій

| Термін | Пояснення |
|--------|-----------|
| **Token** | Шматочок тексту (слово або частина слова) |
| **Embedding** | Вектор чисел що представляє токен |
| **Attention** | Механізм що дозволяє токенам "дивитись" один на одного |
| **Multi-Head Attention** | Кілька паралельних attention-голів, кожна шукає свій тип зв'язків |
| **GQA** | Grouped Query Attention — ефективніша увага (менше KV-голів) |
| **Transformer** | Шар нейромережі: Attention + MLP + нормалізація |
| **MLP** | Feedforward мережа — обробляє кожен токен окремо |
| **Loss** | Помилка моделі (менше = краще) |
| **val_bpb** | Bits per byte на валідаційних даних (менше = краще) |
| **Learning Rate (LR)** | Наскільки сильно змінюються ваги за крок |
| **Batch** | Порція даних для одного кроку тренування |
| **Epoch** | Один повний прохід по всьому датасету |
| **Gradient** | Напрямок зміни ваг (через backpropagation) |
| **Gradient Accumulation** | Накопичення градієнтів з кількох міні-батчів перед кроком |
| **VRAM** | Відеопам'ять GPU |
| **MFU** | Model FLOPs Utilization — % від теоретичної швидкості GPU |
| **OOM** | Out of Memory — не вистачило VRAM |
| **BPE** | Byte Pair Encoding — алгоритм токенізації |
| **RoPE** | Rotary Position Embedding — кодування позиції токена |
| **RMSNorm** | Root Mean Square Normalization — стабілізація тренування |
| **ReluSquared** | Активація `relu(x)^2` — альтернатива GELU |
| **Muon** | Оптимізатор з ортогональними оновленнями (для матриць) |
| **AdamW** | Класичний оптимізатор з weight decay |
| **Warmup** | Поступове збільшення LR на початку тренування |
| **Warmdown** | Поступове зменшення LR наприкінці тренування |
| **Activation Checkpointing** | Економія VRAM за рахунок перерахунку активацій |
| **Skip Connection** | Residual connection — додавання входу блоку до виходу |
| **Value Embedding (VE)** | Додаткові learnable вектори в attention |
| **Sliding Window** | Обмеження діапазону attention для прискорення |
